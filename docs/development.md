# Development

How the project is built, checked and kept honest. Setup is in docs/setup.md; the security rules these conventions serve are in docs/07.

## Stack and constraints

- Next.js 16 App Router, React 19, TypeScript in strict mode, Tailwind CSS 4.
- Route Handlers for HTTP endpoints; server-only modules (`import "server-only"`) for secrets and privileged operations.
- PostgreSQL through `pg`, with plain numbered SQL migrations in `migrations/` (D-002, D-007). No ORM.
- Zod for runtime schemas (HTTP bodies, webhook payloads, environment variables, model output, persisted state).
- Ollama behind a replaceable `LlmProvider` interface (D-003).
- GitHub App access through Octokit (`@octokit/rest`, `@octokit/auth-app`; D-008).
- Vitest and React Testing Library for tests; Playwright only to capture screenshots; GitHub Actions for CI.
- Deliberately absent: Prisma, Express, Vite as an app framework, Zustand, a vector database, a multi-agent runtime, a job queue. Add infrastructure only for a measured requirement (D-005, D-009).
- Core analysis logic stays framework-agnostic: `impact-engine/`, `patches/` and `assist/` import no GitHub, database or Next.js code, and a test enforces it.

Next.js 16 has breaking changes from earlier versions. Before using an unfamiliar Next.js API, read the matching guide in `node_modules/next/dist/docs/`. `agentRules: false` in `next.config.ts` stops `next dev` from injecting agent instructions into the repository.

## Commands

Scripts that need the environment load `.env.local` (`node --env-file-if-exists=.env.local`); the Next.js commands read the usual Next.js env files.

| Command | What it does | Needs |
|---|---|---|
| `npm run dev` / `build` / `start` | Next.js development server, production build, production server | nothing at build time |
| `npm run format:check` / `format` | Prettier check or write (Markdown is ignored by `.prettierignore`) | |
| `npm run lint` | ESLint | |
| `npm run typecheck` | `next typegen` then `tsc --noEmit` | |
| `npm test` | Unit and component tests (`--project unit`) | no database, GitHub or model |
| `npm run test:db` | Database tests (`--project db`), against `docusync_test` | Postgres and the `TEST_*` URLs |
| `npm run test:ollama` | Live model tests (`--project ollama`) | Ollama and `OLLAMA_MODEL` |
| `npm run db:migrate` | Applies `migrations/` as the schema owner | `MIGRATION_DATABASE_URL` |
| `npm run db:check-grants` | Verifies the app role's database limits; run after every restore | `MIGRATION_DATABASE_URL` |
| `npm run ingest`, `analyze`, `propose` | Fixture or live ingestion, impact analysis, and model proposals, printed as JSON | see docs/setup.md |
| `npm run analysis:run` | Runs the pipeline on a fixture or live PR and saves it | database |
| `npm run reviewer:*`, `sessions:prune` | Operator commands for accounts, grants and sessions (owner role) | `MIGRATION_DATABASE_URL` |
| `npm run eval:impact`, `eval:latency`, `eval:llm` | Regenerate the reports in `docs/evaluation/` | `eval:llm` needs Ollama |
| `npm run screenshots` | Capture UI screenshots with Playwright (docs/11) | a running app and a reviewer |

## Verification

CI (`.github/workflows/ci.yml`) runs, in order: `npm ci`, `format:check`, `lint`, `typecheck`, `test`, `build`, then creates the app role and test database with `db/init/01-app-role.sql` and runs `test:db` against a Postgres service. Run the same sequence locally before opening a pull request:

```bash
npm run format:check && npm run lint && npm run typecheck && npm test && npm run build
docker compose up -d --wait postgres && npm run test:db
```

`db:migrate` and the DB tests need Postgres from `docker compose up` (docs/setup.md). The live Ollama tests are opt-in and run on a developer machine only.

**Lockfile on Windows.** `npm install` on Windows drops Linux-only optional packages from `package-lock.json`, which makes `npm ci` fail in CI. After changing dependencies, regenerate the lockfile on Linux:

```bash
docker run --rm -v "$PWD":/app -w /app node:24 npm install --package-lock-only
```

## Evaluation reports

The reports in `docs/evaluation/` are generated by `eval:impact`, `eval:latency` and `eval:llm`; do not edit them by hand. `impact-baseline.md` is pinned by a unit test (`evaluate.test.ts`) that fails when the committed report is out of date. To change its wording, change the generator in `src/lib/impact-engine/evaluate.ts` and re-run `npm run eval:impact`. Rule changes in the engine must be followed by the same command. `eval:llm` records one model run on one machine and is not checked in CI.

## Conventions

- Strict TypeScript with narrow types; avoid `any`.
- Small modules with explicit interfaces and clear error handling. Route Handlers stay thin: parse, authenticate, validate, call services, map errors.
- Keep deterministic logic separate from prompts and model calls.
- Validate every external input at runtime, including model output and persisted state.
- Make operations idempotent where retries are possible.
- Structured, redacted logs through `logEvent`: a closed set of fields, never secrets, tokens, patches or file content.
- Tests cover success, malformed input, edge cases, failure paths and authorization boundaries. Never weaken or skip a test to make CI pass.
- Never commit `.env`, credentials, tokens, private keys, real user data or generated secrets.
- Never claim a feature, test, benchmark, deployment or result that has not been verified. Documentation says which steps are live and which were run against fixtures or fakes.
- Record significant architecture, dependency, permission, schema or scope decisions in docs/decisions.md with the next free `D-NNN` ID.
